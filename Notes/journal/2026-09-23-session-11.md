## Findings

- **F1. Adding the triage sorts is a schema change.** Adding them means widening
  `saved_view.sort_order`'s `CHECK (sort_order IN ('COLDEST_FIRST', 'HOTTEST_FIRST'))`
  ([saved_view.sq](../../shared/src/commonMain/sqldelight/dev/repertosaurus/db/saved_view.sq)
  line 57). SQLite cannot alter a CHECK, so it is a table rebuild. views.md V17a already warns
  that a new `SessionOrder` constant has to change three things: the constant, the CHECK and the
  parse. **So the triage sort names must be fixed before schema 3 freezes.** That is why G1 is a
  hard gate on P1.

- **F2. The Python migration emits no `feel`,** so widening feel to 0–3 does not engage CLAUDE.md's
  two-implementations rule. The workbook's `feel` column is the **groove** (`extract.py:1502`
  writes `facts["groove"]`). The only mention of `practice_event.feel` in `tools/import/` is a
  verification check (`build.py:993`, `feel NOT BETWEEN 1 AND 3`). That check stays correct for
  emitted data, which is always null.

- **F3. Session 10 §4 says its own notes are uncommitted. They are committed** in `c716923`, and
  `1a28fdb` follows it, but neither commit is pushed. Session 10's entry is left as written (the
  journal is append-only). This entry's §2 is the correct state.
