# Session 04 — The App Runs on Real Data

Phase 1 is functionally complete and the user's real repertoire is in it. The Session screen,
add-song, instrument management and the build pass all exist; the migration and the app agree
on every derivable id.

## Where we are

- **19 tables, 124 tests.** SQLDelight generating clean, `assembleDebug` producing an APK.
- **`.scratch/songbook.db`** — 479 songs, 826 practice events, 54 set lists, 5,031 set list
  items, 1,209 staged performers. Verified: `integrity_check` ok, `foreign_key_check` empty,
  `user_version` 1, zero orphaned FKs, zero CHECK or timestamp violations, all four junctions
  reproducing with zero mismatches, and two consecutive builds byte-identical.
- **Delivered to the user** at `D:\Dropbox\Work\Gigs\Songbook\` — APK plus `.db`. Import is
  destructive and repeatable by design, so reloading after further review is the intended flow.

The app has: tap-to-log with optimistic write and working undo, long-press for `feel` and a
note, coldest/hottest sort toggle, search, add-song with the artist type-ahead, a navigation
drawer, instrument management, and import/export.

## Decisions this session

- **Duets — decision 58.** `setlist_item.lead_performer_id` is replaced by a
  `setlist_item_performer` junction ordered by `position`. The user's own framing became 58a and
  is the load-bearing sentence: `song_performer` is who **knows** a song; `setlist_item_performer`
  is who it is **staged with** on one night. Any song can be staged as a duet, so there is no
  `is_duet` flag anywhere. A capped `duet_performer_id` pair was rejected as structurally
  identical to the workbook growing a column per singer.
- **NFC, not NFKC, for id derivation (17a–17c).** Two implementations measured the workbook
  independently and agreed the change was a no-op on this data — which is why it was made now.
  Matching may be lossy; derivation must not be.
- **Typos are not near-misses (17d).** `Fratellis`/`The Fratellis` normalise the same, so they
  derive the same id and converge unaided. `Ukelele`/`Ukulele` normalise *differently*, derive
  different ids and **never** converge. Only the second class needs the UI to defend it, hence
  the capped edit-distance pass in the type-ahead.
- **Junction ids unified (4).** One form for all four junctions.
- **Sparse beats wrong** — where an attribution cannot be confirmed, emit nothing. A missing tag
  is recoverable; a wrong one silently becomes the record.

## Defects found in our own work

Every one caught by an agent other than its author, or by measurement rather than reasoning.

- **The junction id fork.** Decision 4 described junction ids one way and 4a/4d another. Both
  were "derived", nothing said which applied where — so the migration used one form and the
  Kotlin core the other. Measured: **all 507 `song_performer` ids differed.** Nothing would have
  failed loudly. Found only because the migration cross-checked against the Kotlin core; closed
  by verifying 789 ids end to end.
- **A stale comment had hardened the contradiction into the code**, asserting the two forms
  "both satisfy decision 4 and are not interchangeable". Amending a spec does not amend the
  comment beside the implementation.
- **`ORDER BY` inside `GROUP_CONCAT` is unavailable at minSdk 26** — Android 8 ships SQLite
  3.19. The obvious `LEFT JOIN … GROUP BY` form is *not* a substitute: it puts a grouping sort
  between the `ORDER BY` and the aggregate, and SQLite's sorter is not documented as stable, so
  the ordering would be incidental. See the ceiling table in
  [stack-and-delivery.md](../platform/stack-and-delivery.md).
- **The misalignment fix leaked.** Dropping `26-8-23` column A as an artist source *cleared* its
  artist role, which made it **more** eligible for the annotation reader — so six artist names
  became performers. A fix that caused the bug it was adjacent to. Now one
  `is_dropped_column()` predicate every reader consults.
- **`PRAGMA user_version` was unset**, so an imported database would have thrown on first open:
  Android reads 0 as "brand new file" and runs schema creation over existing tables.
- **`GROUP_CONCAT` typed non-null** by SQLDelight, so an item with nobody staged would have
  thrown in the generated mapper — the void anti-join bug reappearing in Kotlin instead of SQL.

## Process lessons

1. **A specific edit outranks a general preference.** The user renamed `R` to Ryan — a decision.
   A later general remark about preferring missing tags was read as retracting it. It did not.
   A general preference governs the *unresolved*.
2. **Amending a spec is half the job.** Twice now the other half — schema, or a code comment —
   was left behind, and both times it was a silent fork rather than a build failure.
3. **Verify against real data, not against your own derivation.** The junction tests pin ids
   lifted from the migration's actual output, so a future change fails against reality rather
   than against a self-consistent expectation.
4. **Test ordering by inserting in the wrong order.** A query that happens to return insertion
   order passes a naive test and fails in the field.
5. **Agents flagged their own bugs mid-task** more than once — a dropped flag on row merge, an
   unearned "contiguous and monotone" claim. Asking for the failure mode explicitly in the brief
   is what produced that.

## Open

- **`practice_context` is unreachable from the UI**, so every event logged is `context_id` NULL
  despite decision 45a. The manage screen was built to generalise — a new kind is an enum entry,
  a store class and a drawer row — but where the *selection* lives is undesigned, since unlike
  instrument it should not need a chip on the Session screen. Largest current gap.
- **No song editing.** A wrong imported key or tempo cannot be corrected in the app, and a song
  added there cannot be given a key. Deliberately deferred pending real use.
- **The review workbook keys on `song_id`**, which derives from artist and title — the fields
  the human edits. Recorded as a design fault; the fix is a provenance key (source worksheet +
  cell). Not needed again unless another review round happens.
- **iOS and JS `actual`s for `unicodeNormalise`** are owed at phases 4 and 5.
- `venue` is empty by design; song duration and set targets have no source anywhere.
- Unverified without hardware: everything visual and tactile. Drawer gestures, the scrolling
  chip row, IME behaviour in the add sheets, and query performance against the full repertoire.
