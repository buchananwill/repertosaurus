  better to have too many options than anything be inaccessible."* The user will decide over time
  which surfaces to foreground and which to push behind a menu dive.

## Findings

- **F1. The capability editor is reachable in the current build but was not discoverable.** The
  user did not find long-press → *Who plays this* after a month of daily use. E2's choice to put it
  behind the long-press sheet kept feel-rating cheap but made the editor effectively invisible.
  Evidence: the user's report this session.
- **F2. The capability editor cannot reach a song outside the active View.** It is entered from a
  logger row, and the logger shows only View-eligible songs — so the editor cannot add a song to a
  repertoire the View filters on. This is the concrete mechanism behind "inaccessible".

- **F3. The baseline is red at a commit session 08 recorded as green: 9 of 253 shared tests fail,
  all in `SchemaCompatibilityTest`, and the cause is line endings, not code.** `core.autocrlf=true`
  checks [schema-v1.sql](../../shared/src/androidUnitTest/resources/schema-v1.sql) out as CRLF
  (`git ls-files --eol`: `i/lf w/crlf`, no attribute), and `SchemaV1Fixture.statements` splits on
  the literal `"\n--;\n"`, which never matches `\r\n--;\r\n` — so the dump replays as one statement,
  the `instrument` table is never created, and every test downstream reports `no such table:
  instrument`. Session 08's green run predates the user's out-of-session directory rename, which is
  the most likely point the working tree was re-checked-out. The repo has no `.gitattributes`, so
  every fixture whose parser splits on `\n` is exposed the same way.

- **F4. Song and artist ids are derived from fields this arc makes editable.** `Ids.song(artistId,
  title)` and `Ids.derived("artist", name)`; `createSong` and `findOrCreateArtist` return any row
  already holding the derived id **untouched, even if it is tombstoned**. Ruled on in R21–R23: no
  re-derivation, revive tombstones, and name the row an add resolved to. Evidence:
  `RepertosaurusRepository.kt:298-349`, `LookupTables.kt:340` (the lookups already revive).
- **F5. E32's aggregate split has not happened; only E31's lookup cut landed.** The repository is
  639 lines. R30 makes `SongCatalog` the second cut.
- **F6. `SessionViewModel` is the only ViewModel (1,058 lines) and E45's serialisation is a ticket
  that drops stale results, not a mutex** — writes still run concurrently on IO. R8 therefore
  states the property for the toggle list rather than reusing the ticket.
- **F7. `song_instrument` (difficulty, patch, notes) exists and nothing in the app reads it.** R19
  exposes it.
