# Session 08 — The Name Reverses Again: Repertosaurus

No feature work. `Repertaurus` became **Repertosaurus**. Session 05 named and cleared
`Repertaurus` five days ago, weighing it against `Repertosaurus` and choosing the shorter name on
preference. That preference didn't survive contact with daily use.

## Where we are

- **The product is `Repertosaurus`, not `Repertaurus`.** Full reversal recorded in
  [naming.md](../decisions/naming.md) N15–N24; N1–N14 stay untouched as the historical record of
  how `Repertaurus` was chosen, cleared, and rolled out.
- **Why:** N4 accepted, back in session 05, that `Repertaurus` and its dinosaur logo point at two
  different animals — `-taurus` is Latin for bull, the logo is a dinosaur — and decided that was
  fine because the logo alone carries the dinosaur reading. It wasn't fine. The bull collision kept
  surfacing in daily use and got worse with familiarity rather than better. `Repertosaurus` removes
  it by construction: `-saurus` reads as dinosaur to everyone, so the word and the logo finally name
  the same animal. Pronunciation: `re-per-to-SAU-rus`, same falling-close metre as `Brachiosaurus`.
- **Clearance audit re-run against `Repertosaurus` specifically (N19), and it came back cleaner
  than `Repertaurus` did.** Zero exact-string collisions — GitHub, npm, PyPI, crates.io, Docker
  Hub, both app stores, open web search, all fresh as of today. The trademark register is still
  unreachable by automation (same wall N7 hit for `Repertaurus`; permanent for either name). The
  only crowded field is `-saurus` in dinosaur AR/quiz/zoo-sim apps — no music apps, no shared trade
  channel, the same "remote goods" reasoning N8 used to clear `TAURUSX`. No curveball surfaced;
  the reversal proceeded straight to execution as instructed.
- **The rename landed and is verified, not just executed.** `git mv` across 7 package-directory
  moves spanning every Kotlin source set plus the SQLDelight `db` directory (`.sq`/`.sqm` content
  byte-identical — directory move only); 3 files renamed with their symbols
  (`RepertaurusApp`→`RepertosaurusApp`, `RepertaurusRepository`→`RepertosaurusRepository`,
  `RepertaurusDatabaseTest`→`RepertosaurusDatabaseTest`); `rootProject.name`, both modules'
  `namespace`/`applicationId`, the SQLDelight database class and package; `DATABASE_NAME`,
  `exportFileName`'s prefix, `AppGraph.PREFERENCES`; four user-facing/rejection strings; the Python
  migration's paths, `GENERATED_IMPL` and prose — `extract.py` was edited, never executed, per
  [import-songs-2026.md](../migration/import-songs-2026.md)'s "the review file is the human's, not
  the pipeline's" rule.
- **`songbook.dev` (N13's UUID v5 root) is untouched, and this was proven, not assumed.** The
  safety reviewer re-derived all **1,356 real ids** in the regenerated database against that root
  and cross-checked 7 of `IdsTest.kt`'s pinned literals against the Python implementation
  independently. Zero mismatches. The fourth id fork this project has had (session 07) did not
  become a fifth.
- **Both reviewers, independently, caught the same miss**: `normalisation-vectors.tsv` — the file
  built specifically so decision 41's Kotlin/Python normalisation agreement is asserted once, in a
  file neither implementation owns, rather than in prose either side could drift from alone — still
  pointed at the old `dev/repertaurus/core` path. Its Python-side twin comment in `extract.py` had
  been updated in the same diff; this file's mirror-image comment was the one the bulk pass missed.
  Fixed, two lines, no vector content touched. The style reviewer also caught a broken anchor link
  in `naming.md`'s own new supersession banner (an em-dash in the heading strips to a double hyphen
  in the slug). Fixed.
- **Re-verified clean from a genuinely clean build**, not just `--rerun-tasks`: `gradlew clean` then
  `build --rerun-tasks --no-build-cache` — `BUILD SUCCESSFUL`, **172/172 tasks executed**, 506
  shared-test results (253 tests × debug/release), 0 failures. This was worth doing because the
  safety reviewer flagged stale `RepertaurusDatabase`-named generated Kotlin still sitting under
  `shared/build/` after the first rebuild — harmless (not on the compile path, gitignored), but it
  meant the first green build wasn't proof against a pre-rename artifact. Now it is.
- **Repository directory is now `D:\coding\repertosaurus`** — N24's first half is done. The user
  renamed it out-of-session with the tooling closed, which is what N14 and N24 both said it would
  take. Confirmed to have broken nothing: `gradlew projects` resolves `Root project
  'repertosaurus'` with both modules, `:shared:testDebugUnitTest` and `:androidApp:assembleDebug`
  both `BUILD SUCCESSFUL`, and the Python normalisation-vector check passes. No absolute repo path
  was ever baked into a tracked file — `local.properties` carries only `sdk.dir`, and `.gradle/`,
  `build/`, `.idea/` and `local.properties` are all gitignored. `.idea/` still holds the original
  `songbook.iml` module name and a stale `last_opened_file_path`; it is IDE-local and gitignored,
  and Android Studio regenerates it on the next sync.
- **The Dropbox delivery folder (`D:\Dropbox\Work\Gigs\Songbook\`) is still unrenamed** — N24's
  second half, still outstanding, still a standalone step.
- **Committed.** The whole reversal — `naming.md`, every other doc, and the full code rename — went
  in as one commit on `feature/views-and-editing`: 75 renames staged as renames so history stays
  attached, plus 22 content edits and this entry.

## Open questions

- **The trademark-register gap is permanent and unresolved for either name** (N7, restated at
  N19). `tmsearch.uspto.gov` is a JS shell; `uspto.report` 403s. The only real closes — a Google
  Play Console name reservation, a paid or attorney-run register search — remain undone.
- **The persistence/UX identifier test gap, re-raised by the safety reviewer (their N2), is now
  two renames deep with still no test.** `DATABASE_NAME`, `exportFileName`'s prefix and
  `AppGraph.PREFERENCES` have each changed value twice with nothing in the suite asserting either
  value. Session 07's `naming.md` follow-up already named the fix — one JVM test over
  `DatabaseHolder` with a temp-dir `Context` double. Still not built. Not urgent while nothing has
  shipped (the coupling argument holds: `applicationId` changes in the same piece of work both
  times, orphaning the data directory anyway) but it is the same accepted gap surviving a second
  cycle unaddressed.
- **`naming.md`'s N14 follow-up describing a literal NUL byte in `DatabaseHolder.kt` is now
  false** — the safety reviewer byte-scanned the file at `HEAD` and found it clean; the byte was
  evidently removed during the session 07 editability arc without the follow-up being retracted.
  Left as-is this session (it's inside N14's preserved-history block), noted here for whoever next
  touches that section.
- **The logo is still undrawn.** N9's Jurassic-Park-device-mark risk and N11's illustrator brief
  are untouched by this reversal and apply exactly as written to `Repertosaurus`'s logo, whenever
  it gets drawn.
- Carried forward untouched: `practice_context` unreachable from the UI, no song editing, the
  phase 2 sync spec unwritten, `jvm()` target still the cheapest structural win, nothing has run on
  physical hardware.
