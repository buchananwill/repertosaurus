## What the extract found that the spec had wrong

The migration spec was written from a markdown export that lost worksheet names and a third of
the rows. Measuring the real `.xlsx` corrected it repeatedly. The corrections are recorded in
[import-songs-2026.md](../migration/import-songs-2026.md); the ones that changed the design:

- **No song duration exists anywhere in the workbook.** The `Order` values read as seconds
  (`216`, `230`, `300`) are `set × 100 + position`. The set list running-time feature therefore
  starts empty and has no import source.
- **No `NxM` set-length string exists**, so `target_minutes` has no source either. Those
  examples came from a different workbook (the gig-booking sheet).
- **Dates in 2099 do not exist**; nor do year-less dates. Both were export artefacts.
- `bass difficulty` runs `a`–`e`, not `a`–`c` — a three-value CHECK would have discarded 56
  cells.
- Artist folding needs 9 events, two of them pure trailing whitespace.
- `Kendra Piper` is a Title-column header holding 190 titles, not a singer column.

## Corruption found in the source, and what it teaches

- **Tab `26-8-23` has a sort desync**: its unheaded artist column is offset by a row against an
  alphabetical title column. Verified 0/6 aligned, 5/6 at +1 — and the sixth sits at +2, which
  is why **no shift repair was applied**. The column is dropped as an artist source. A general
  detector now scores every inferred artist column at offsets 0/±1 against pairs harvested from
  columns the workbook itself headed Artist/Title.
- **`14-5-22` genuinely says `Radiohead | Don't Stop Me Now`.** A real typo, not a
  misalignment. It prompted a new cross-tab `ARTIST-DISAGREEMENT` check: 16 rows across 8
  titles. Most are not errors — they are cover attributions (`Soul Man`: Blues Brothers vs
  Sam & Dave), two are aliases to merge, and `Someone Like You` is genuinely two different
  songs. **This is decision 23 earning its keep**: the review question is "whose arrangement do
  you play", not "who wrote it".

## Defects found in our own work

Recorded because each was caught by a *different* agent than wrote it, which is the operating
model working.

- **The staleness query filtered songs out instead of returning them to never-practised.** The
  void anti-join sat in `WHERE` rather than `ON`, so undoing the only log for a song deleted it
  from the Session list — the opposite of decision 8, on the highest-frequency path. Now a
  `NOT EXISTS` inside the join, with a named regression test.
- **`days_since` was a guaranteed NPE on launch.** SQLDelight types the `CAST` as non-null and
  generates `getLong()!!`; SQLite returns `NULL` for a never-practised song, which is the first
  row the ordering returns. Moved into the shared core, per decisions 48 and 57.
- **2,704 cells were silently dropped** by the first extract — no `else` branch, and the
  "deliberately skipped" list was dead code. Two songs (*Big Yellow Taxi*, *Dancing Queen*)
  existed only in an unheaded column and were lost outright. Cell accounting is now a hard gate:
  every non-blank in-scope cell reaches a data sheet or `Unresolved`. 0 unaccounted.
- **`normalise` deleted punctuation instead of replacing it**, so `AC/DC` keyed as `acdc`,
  corrupting permanent ids and guaranteeing the app's type-ahead would never match a migrated
  row.
- **Schema and spec drifted** because the `.sq` files were written before the spec was revised
  and nobody propagated: `difficulty` CHECK 1..3 vs 1..5 (would have failed the migration on 55
  rows), `artist_id` nullable vs NOT NULL, and the `band` table referenced by four decisions and
  created by none.

## Ratified this session

- **4d** — song canonical key is `artist_id + "/" + normalise(title)`. The separator is fixed.
- **4e** — punctuation is anything not a Unicode letter or digit; the underscore is handled
  explicitly because Python's `\w` includes it and `isLetterOrDigit()` does not.
- **17/17a/17b/17c** — Unicode **NFC** first, in every implementation, for id derivation. NFKC
  only ever as an extra *matching* pass. Two implementations measured the workbook
  independently and agreed the change was a no-op on this data — which is why it was made now.
  The fork it prevents is real: macOS and iOS emit decomposed accents, and one pasted ligature
  forks an id permanently with nothing looking wrong on screen.
- **28a** — `artist_id` NOT NULL, with a seeded `Unknown Artist`
  (`cf06771d-4e8d-53fc-83fb-359be7dfaefc`).
- **42** — difficulty 1..5.
- **49a/b/c** — `band` is a first-class table. Blue Lion is a **band**, not a venue; the user
  corrected an inference made from tab names. Band and venue are different dimensions.
- **56a** — enharmonic respelling fires only when `transpose ≠ 0`, so a stored C♯ major
  displays as entered.

## Process lessons worth keeping

1. **Never regenerate a review file the human is editing.** Done twice mid-review here. The
   edits survived only because they could be re-matched on title — a field under revision. The
   review workbook needs a provenance key (source worksheet + cell), not a derived id, because
   a derived id is a function of exactly the fields the human is there to correct.
2. **Scope agent tools explicitly.** An agent briefed to use the Drive MCP reached for Playwright
   against the user's authenticated Google session on its own initiative. See the tool-scoping
   policy in [CLAUDE.md](../../CLAUDE.md). Acquire external data at the top level and hand agents
   a local path.
3. **Adversarial review before hand-off pays.** Three of the four serious schema findings were
   *internal contradictions* — decisions in one document that could not both hold. An author
   does not catch those.
4. **Do not accept an agent's assertion as evidence.** One emitted a note claiming a series was
   "contiguous and monotone" while testing neither. The conclusion happened to be right; the
   claim was unearned and was repeated onward before a reviewer checked it.
