# Session 05 — The App Gets Its Name

No feature work. The working title was replaced with a real one, the rename was executed twice,
and the second pass produced the strongest verification this project has yet done.

## Where we are

- **The app is `Repertaurus`.** Tagline: **"Don't let your repertoire fossilize."** A dinosaur
  logo is intended and has not been drawn. The full contract is
  [naming.md](../decisions/naming.md), N1–N14.
- **The rename is landed on `main`** — three commits, fast-forwarded from `rename/repertaurus`.
  63 files, 49 moves staged as renames, 124 tests, byte-identical database.
- **Phase 1 is functionally unchanged.** Nothing about behaviour moved; this was a rebrand.
- **Outstanding:** the repository directory is still `D:\coding\songbook`. It cannot be renamed
  from inside a live session — see "What could not be done" below.

## Decisions this session

- **N1 — the name is `Repertaurus`.** A coinage, so it is inherently distinctive and clears the
  descriptiveness bar. Zero hits on every surface searched.
- **N3 — the tagline names the mechanic.** "Don't let your repertoire fossilize" was chosen after
  the name, and is better than the name deserved: the Session screen already sorts coldest-first,
  so *a song going cold is the thing being tracked*. The dinosaur stops being a decorative pun and
  becomes the product's own metaphor. The "monster performer" idea that motivated the name
  survives as brand voice, not copy.
- **N4 — the word and the logo point at different animals, deliberately.** `-taurus` is Latin for
  bull; dinosaurs are `-saurus`. The dinosaur reading is carried entirely by the logo. Recorded so
  nobody later "corrects" the spelling.
- **N8/N9 — the exposure is in the logo, not the name.** Name risk LOW; logo risk MODERATE.
- **N13 — `songbook.dev` survives the rename permanently.** The UUID v5 root namespace is an
  opaque derivation seed, not a brand. This is the load-bearing exclusion.

## The reversal: Repetorious → Repertaurus

**A name was chosen, specified, renamed throughout and committed — and then reversed.** Recorded
in full because the reasoning matters more than the outcome.

`Repetorious` was selected first and reached two commits on a branch. Three names were floated
after it, and `Repertaurus` won. The reversal was cheap **only because the work sat on an unmerged
branch**; `main` never saw Repetorious, so the second pass was cut fresh from `main` rather than
stacked on top, and the history is clean.

Why each candidate died is in N12. The two worth remembering:

- **`Repertorio`** was rejected not as dangerous but as **unownable**. It is the dictionary word
  for the product's own category in three languages, and TMEP 1209.03(g) refuses the foreign
  equivalent of a descriptive English word (SAPORITO for sausage, LAPELLE for leather furniture).
  Safe to use, impossible to own — a distinction worth carrying forward.
- **`Reposaurus`** metrically beat everything else and died on meaning. A deliberate search for
  evidence that musicians clip "repertoire" to "repo" **found none**; the live senses are git
  repository, repossession and repurchase agreement. `pip install reposaurus` also resolves today.

**A correction the user made, and was right about.** The session argued that a missing `r` would
be misspelled. The user pointed out that in non-rhotic English `reper-` and `repe-` are both
/ˌrɛpə/, that musicians are disproportionately dyslexic or ADHD with idiosyncratic spelling, and
that people drop letters that carry no sound (*suprise*). The argument had been presented as a
finding when it was an assumption. Separately, an auto-correct result was given decisive weight it
had not earned — every coined name auto-corrects before it has any web presence.

## Process lessons

1. **The second rename was better because the first one's near-misses were written into the
   brief.** The `DatabaseHolder.kt` NUL byte, the six extra identifiers, the `songbook.dev`
   exclusion and the `FROM-CACHE` trap were all discovered in pass one and became *instructions*
   in pass two. The cost of the reversal was largely repaid by the quality of the redo.
2. **Un-rename the diff and compare.** The reviewer took every `HEAD` blob, applied the brand
   substitution mechanically with `songbook.dev` protected by a sentinel, and diffed that against
   the working tree: **63 of 64 files byte-identical**. That is a proof, not an inspection, and it
   cannot miss a semantic change hiding in a large mechanical diff. **Reuse this technique for any
   future rename or bulk mechanical edit.**
3. **`BUILD SUCCESSFUL` is not evidence that tests ran.** The first clean build reported
   `:shared:testDebugUnitTest FROM-CACHE`. Gradle served cached results and proved nothing. Force
   `--rerun-tasks --no-build-cache` and confirm the task actually executed.
4. **A NUL byte makes a file invisible to grep.** `DatabaseHolder.kt` carries a literal `0x00` in
   a KDoc comment, so git and ripgrep classify it as binary and **silently skip it**. Pass one
   missed two brand strings there. Pass two swept in binary mode instead. **Any completeness audit
   that relies on grep is unsound while that byte is there** — the fix is to escape it as
   `\u0000`, and it has not been done.
5. **Capture your own baseline.** Pass two ran the migration *before* touching anything, then
   compared SHA-256 after, rather than trusting row counts quoted from a previous session.
6. **Silence in a spec is a defect.** The first review blocked on a bookkeeping gap: N9 listed the
   repository directory in scope, and the follow-ups recorded the Dropbox folder as deferred but
   said nothing about the directory. One enumerated item silently incomplete while its sibling was
   explicitly deferred reads as an oversight. Deferral is fine; **unrecorded** deferral is not.
7. **Register interfaces are closed to automation, and this never improved.** Across five names
   and four dossiers, USPTO returned a JS shell, EUIPO site chrome, TMview reset the connection,
   and Justia and Trademarkia returned 403. The one route that worked is **USPTO TSDR by serial
   number**, which is genuine primary-source data but needs the serial first. Every register fact
   in naming.md is verified; every *absence* is not.

## What could not be done

**The repository directory could not be renamed from inside the session.** Diagnosed rather than
assumed: the Gradle daemon was stopped and the rename still failed; a process check found **no
JVMs running at all**; and an attempt to move the Bash shell out had its working directory **reset
by the harness**. Claude Code pins the directory as its cwd and Windows will not rename a directory
in use. It must be done with the session closed:

```powershell
Rename-Item -Path "D:\coding\songbook" -NewName "repertaurus"
```

Verified safe: no source or tooling file hardcodes an absolute repo path — `tools/import/build.py`
derives `REPO` from `__file__`, and the only absolute path in the tree is `USER_XLSX`, pointing at
Dropbox. Expect an IDE re-index and a clean first build; both artefacts are gitignored.

## Open

- **The logo does not exist.** N11 carries the illustrator's brief — hand it over *before* anyone
  draws, because the default dinosaur logo is Universal's registered mark. The two operational
  safeguards (written assignment of copyright with a no-AI-derivation warranty; a
  Vienna-classification device search before launch) are also unactioned.
- **No trademark register has been searched.** The position on `Repertaurus` is **unknown, not
  clear**. A Play Console name reservation is the cheap definitive check on the store namespace.
- **The Dropbox delivery folder** `D:\Dropbox\Work\Gigs\Songbook\` is unrenamed, and **there is no
  current APK** — `clean` removed the one the rename produced. A fresh build and delivery is a
  separate step.
- **The old app must be uninstalled from the phone.** The new `applicationId` installs *alongside*
  rather than upgrading, so two icons and a stale database otherwise.
- **The NUL byte in `DatabaseHolder.kt`** is unescaped, so grep-based audits remain unsound there.
- **None of the persistence and UX identifiers changed by the rename is under test** — the suite
  runs in-memory and never reaches `DatabaseHolder`, the filenames, the preferences file or the
  import/export round-trip. One JVM test with a temp-dir `Context` double would cover the class.
- Everything carried forward from session 04 is untouched: `practice_context` unreachable from the
  UI, no song editing, the phase 2 sync spec unwritten, and the first four architecture-review
  items outstanding.

and can be deleted whenever.
